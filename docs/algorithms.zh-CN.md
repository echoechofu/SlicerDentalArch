# 算法使用说明与测量协议

[English](algorithms.md) · [项目首页](../README.zh-CN.md) · [编辑器说明](editor.zh-CN.md)

## 1. 输入条件与适用范围

当前实现要求完整的 14 牙上颌，每侧包括中切牙、侧切牙、犬牙、两颗前磨牙和两颗
磨牙。每颗牙冠必须是可独立识别的连通网格组件；STL 可以同时包含底座等其他组件，
通过人工复核的牙位映射将它们排除。

这一步**不是从连成一体的口扫网格中自动分牙**。组件检查按共享流形边连接三角形，
输入本身必须已具备独立牙冠表面。被选中的牙冠必须封闭、流形、非退化，并保持一致
的朝外面片方向。程序不会自动修补、缩放、补洞或推断缺失牙。

目前只接受二进制 STL，文件长度必须与声明的三角形数量一致。顶点采用精确匹配，
不进行容差焊接。重新导出、改变三角形顺序、修复或修改 STL 会改变源文件哈希，也
可能改变组件编号；此时必须重新检查和复核。

坐标方向、牙位和解剖含义均需人工确认。当前不支持局部牙弓、缺失牙、第三磨牙、
下颌，也不自动推断临床牙位编号。

## 2. 检查模型与复核配置

使用 Slicer 自带的 Python 运行算法。以下为在仓库根目录执行的 PowerShell 命令，
请替换成自己的软件和文件路径：

```powershell
& "C:\path\to\Slicer\bin\PythonSlicer.exe" algorithms/inspect_stl.py --input model.stl --output-dir work/inspect
```

检查阶段输出：

| 文件 | 用途 |
| --- | --- |
| `components.json`、`components.csv` | 所有组件的编号、范围和网格检查结果 |
| `inspection_top.png`、`inspection_bottom.png` | 初始坐标框架中的带编号组件概览，标记最大的 32 个组件 |
| `config.template.json` | 与源文件绑定的配置模板；组件未分配，复核标志为 false |

把模板复制到私有的配置文件中，结合 3D 模型检查概览图。PCA 只提供初始框架建议：
轴的顺序和正负方向需要解剖复核，才能使后续“顶面”检测具有正确含义。

坐标变换如下：

```text
q = (原始坐标 - alignment.center) @ alignment.axes_columns
原始坐标 = q @ alignment.axes_columns.T + alignment.center
```

矩阵的三个列向量分别表示横向、前向和咬合面方向。应确认 qY 正方向指向前牙，
qZ 正方向指向咬合面/切缘。在 qY 朝上的咬合面预览中，VL 对应 qX 负侧，
VR 对应 qX 正侧。矩阵必须正交归一且为右手系，不能包含缩放或剪切。旋转只改变
分析框架，不改变保存的原始坐标。

### 配置字段

请修改本次检查生成的模板，不要沿用其他病例的坐标或组件编号。

| 字段 | 要求 |
| --- | --- |
| `schema_version` | `1` |
| `sha256` | 本次复核的准确 STL 文件哈希，由检查脚本生成 |
| `alignment.center` | 3 个有限的原始坐标值 |
| `alignment.axes_columns` | 3 × 3 有限、正交归一、右手系矩阵 |
| `orientation_reviewed` | 目视确认方向后设为 `true` |
| `tooth_mapping_reviewed` | 确认组件与牙位对应后设为 `true` |
| `regions` | 完整 14 项，每项含规定的 `id`、`kind` 和唯一非负整数 `group` |
| `groove_anchors` | 可选，前磨牙 ID 对应两个对齐坐标系 XY 牙尖锚点 |

VL、VR 两侧分别使用以下 7 个后缀：

| 后缀 | kind |
| --- | --- |
| `I1` | `central_incisor`，中切牙 |
| `I2` | `lateral_incisor`，侧切牙 |
| `C` | `canine`，犬牙 |
| `P1`、`P2` | `premolar`，第一、第二前磨牙 |
| `M1`、`M2` | `molar`，第一、第二磨牙 |

这些侧别标签属于预览坐标约定，不代表程序已经判断患者左右或 FDI 编号。牙齿身份
仍需根据原始模型确认。不要仅为绕过检查而把两个复核标志改成 true。

可选的 `groove_anchors` 为前磨牙颊舌两侧牙尖位置，格式为
`[[qX, qY], [qX, qY]]`。它们建立中央沟搜索走廊，并非最终近远中点。
未提供时，程序暂用两个检测到的牙尖候选；若某颗前磨牙不足两个候选则停止该流程。
无论采用哪种方式，最终中央沟方向和测量点都需要解剖复核。

### 坐标尺度

结果保持原始坐标单位，程序不推断物理单位。检测包含固定坐标长度的采样步长、
平滑尺度及候选间距，默认值是在毫米量级的牙齿坐标中开发的。使用其他尺度前，应
先查看组件范围并调整源码中的相应参数。参考牙弓优化虽采用归一化坐标，也不意味着
前面的牙尖和近远中检测具备尺度不变性。

## 3. 运行流程

同时生成算法结果和已初始化的 Slicer 场景：

```powershell
& "C:\path\to\Slicer\Slicer.exe" --ignore-slicerrc --disable-settings --no-main-window --no-splash --python-script algorithms/run_in_slicer.py -- --input model.stl --config reviewed.json --output-dir output/session
```

请使用新的或空的输出目录，程序拒绝覆盖已有结果。此命令启动独立的批处理 Slicer
进程；其他已打开的 Slicer 会话中的工作应单独保存。

仅运行数值算法、不生成场景：

```powershell
& "C:\path\to\Slicer\bin\PythonSlicer.exe" algorithms/run_all.py --input model.stl --config reviewed.json --output-dir output/session
```

两种命令均可追加 `--skip-sensitivity`，跳过切缘、近远中测量和参考牙弓的额外敏感性分析。参数敏感性分析
反映拟合设定的影响，并不代表临床测量不确定度。

| 产物 | 内容 |
| --- | --- |
| `landmarks/landmark_candidates.json` | 原始/对齐坐标下的牙尖和中央窝候选 |
| `incisal/incisal_results.json` | 四条切缘曲线及中点 |
| `mesiodistal/mesiodistal_results.json` | 各牙近远中点、方向、宽度及复核信息 |
| `arch/reference_arch_results.json` | 解析曲线定义、参考平面、端点和拟合参数 |
| `crowding_results.json` | 所需长度、可用长度和有符号差值 |
| `resolved_config.json` | 本次实际使用的配置 |
| `pipeline_manifest.json` | 各阶段状态及源文件信息 |
| `DentalArchScene.mrb` | 封装模型、算法基线和可编辑状态的完整场景 |
| `scene_validation.json`、`pipeline_status.json` | 场景创建检查及批处理完成状态 |

各阶段还会生成相关 CSV。场景部分需要通过 `run_in_slicer.py` 运行。
配置、源文件哈希、日志、截图和坐标也属于病例数据，公开分享源码时应一并排除。

## 4. 算法原理

### 牙尖与中央窝

对各牙冠建立咬合面高度图，通过去趋势、多尺度平滑、局部高度和凸性条件提出牙尖
候选。候选上限为每颗犬牙 1 个、每颗前磨牙 2 个、每颗磨牙 4 个，因此在当前 14 牙
设定中最多 26 个牙尖，并不保证每次都输出这个数量。四颗磨牙另在牙冠内部搜索凹陷，
表面证据足够时提出中央窝候选。候选评分和几何检查是启发式规则，不是解剖正确率。

### 四颗切牙切缘

只对四颗切牙生成切缘曲线。先确定较高的切缘带，再通过带平滑约束的路径搜索得到
曲线，并投影回牙齿表面，输出曲线和中点。切缘端点的选取具有启发式性质。
犬牙沿用牙尖点，不生成犬牙两侧切嵴。

### 近远中测量点 v2

前磨牙在颊舌牙尖锚点之间建立搜索走廊，利用凹性、坡度和路径平滑寻找中央沟，
由拟合后的中央沟方向引导近远中截线。磨牙根据牙冠外形估计方向。后牙候选端点
限制在沿已复核 qZ 方向计算的**分离牙冠几何高度最上 1/3**，结合相向的邻面法向
寻找宽度线段，并排除穿过不合适中间表面的候选。

这里的几何高度并不是临床识别的釉牙骨质界，也不是每颗牙单独拟合的长轴。分割边界
或全局方向错误会改变“最上 1/3”的含义。前牙保留前牙的宽度检测方法。

结果是每颗牙固有近远中宽度的**测量点对**，不一定就是与邻牙实际接触的位置，
尤其在旋转或存在间隙时。应在场景中检查前磨牙中央沟方向、端点高度和牙位归属。

### 参考牙弓

默认使用具有 7 个控制点的平面三次 B 样条，按当前总体牙弓形态平滑局部错位，
不强制左右对称。拟合输入是第二前磨牙到对侧第二前磨牙的 20 个近远中点，两侧
第一磨牙近中点在参考平面上的投影作为固定端点。

每颗牙的总权重相同，采用 Huber 残差与二阶导数平滑惩罚，在归一化坐标中求解。
默认平滑惩罚权重为 `1e-4`，Huber 转折尺度为端点距离的 1.5%。
精确求解和可选敏感性变体以源码为准。曲线控制点、节点向量和次数是计算依据；
501 个采样点用于显示。

参考平面平行于已复核的 qXY 平面，高度为两侧第一磨牙近中点 qZ 的均值。
原始点的高低起伏不会增加可用牙弓长度。

## 5. 拥挤度的数学定义

设 `M_i`、`D_i` 为第二前磨牙到对侧第二前磨牙共 10 颗牙的原始三维测量点，
`B(t)` 为两侧第一磨牙近中投影点之间的平面解析参考曲线：

```text
单牙宽度 w_i = ||M_i - D_i||₂
所需长度 R   = Σ w_i
可用长度 A   = ∫₀¹ ||B′(t)||₂ dt
拥挤度   C   = R - A
间隙差   D   = A - R
```

C 为正表示净长度不足，为负表示净剩余，单位仍为原始坐标单位。第一磨牙宽度
不计入 R，第二磨牙位于测量范围之外。这是一个明确的参考曲线测量协议，不能代表
所有临床牙弓间隙测量方法；不自动判断严重程度，也不建议扩大多少牙弓。
总长度有剩余时，仍可能存在局部拥挤或旋转。

## 6. 在 Slicer 中复核与修改

安装并打开 DentalArchEditor，然后载入生成的 MRB。算法结果保留为基线，另有
独立的工作状态供修改。

调整内部牙齿测量点会改变 R，但不会静默重拟合已编辑的牙弓。两侧第一磨牙近中点
与参考牙弓边界联动。五个内部控制点可以调整，两个端控制点与边界绑定；
需要重新拟合时使用明确的 **Refit** 操作。

手动修改允许偏离算法候选。方向或高度变化会触发复核提示，程序不会悄悄把点移回
算法位置。[编辑器说明](editor.zh-CN.md)详细介绍表面吸附、曲线有效性、变换限制、
撤销及修订保存。MRB 保存数据而不保存运行中的 Python 回调，重新载入后需要打开
已安装的模块来恢复实时计算。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 整个牙弓只有一个融合组件 | 先完成分牙和独立牙冠准备 |
| 牙冠不封闭、非流形或方向错误 | 在合适的网格工具中修正后，重新检查和复核新 STL |
| 源文件哈希不匹配 | 检查准确的当前文件，不沿用改变前的导出配置 |
| 复核标志仍为 false 或组件未填写 | 完成坐标方向及 14 牙映射复核 |
| 检测点跑到模型底面 | 检查 qZ 是否朝咬合面，以及牙冠边界是否正确 |
| 候选数量异常、前磨牙方向不合适 | 检查尺度、表面形态、牙位及牙尖/中央沟锚点，并人工复核 |
| 输出目录已有结果 | 使用新的输出目录 |
| MRB 打开后拖点不更新 | 安装并打开 DentalArchEditor，使用已初始化的场景 |
